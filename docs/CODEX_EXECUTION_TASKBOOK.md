# JLZ-EDU-SK-094 Codex执行任务书

## 1. 基线

- 任务编号：`JLZ-EDU-EXPANSION-30-FULL-DELIVERY`
- 候选来源：`CAND-039`
- 正式产品：`JLZ-EDU-SK-094` / 教师工作量与排班负荷审计
- 类型：Skill

- 业务中心：13 组织与人才效能中心
- 版本基线：`EDUCATION_BASELINE_V1.0.0`
- 产品版本：`1.0.0`
- 许可证：Apache-2.0

## 2. 用户、痛点与目标

- 用户：校长、教务、HR、教学主管
- 痛点：教师负荷只看课时数，忽略备课、作业反馈、家校沟通、跨校区通勤和连续授课，容易出现疲劳和质量波动。
- 目标：汇总教学与非教学任务，检查负荷分布、连续工作、通勤和高峰冲突，提出可执行调整。

## 3. 输入契约

| 键 | 名称 | 类型 | 必填 |
|---|---|---|---|
| `teachers` | 教师清单 | array | 是 |
| `schedule_entries` | 课表与任务 | array | 是 |
| `task_time_standards` | 任务工时标准 | object | 是 |
| `commute_data` | 跨校区与通勤 | array | 否 |
| `rest_rules` | 恢复窗口与限制 | string | 是 |
| `role_scope` | 岗位范围 | string | 是 |
| `audit_period` | 审计周期 | string | 是 |

## 4. 工作流

1. 建立任务清单
2. 汇总每周负荷
3. 检查连续与通勤
4. 比较团队分布
5. 识别高风险
6. 生成排班/减负建议

## 5. 阶段状态

| 阶段 | 动作 | 退出成果 |
|---|---|---|
| S1_SCOPE_CONFIRMATION | 确认目标、校区/岗位/课程范围、期限、交付格式和可用资料。 | 任务确认单与最多3个关键缺口 |
| S2_EVIDENCE_INVENTORY | 盘点教师名单、课表、备课/作业/沟通标准工时、跨校区安排、休息时间、岗位职责、个人限制（可选），标记来源、版本、敏感字段与冲突。 | 证据清单、缺口表和冲突表 |
| S3_PROFESSIONAL_DIAGNOSIS | 围绕汇总教学与非教学任务，检查负荷分布、连续工作、通勤和高峰冲突，提出可执行调整。进行专业诊断，形成问题树和优先级。 | 问题树、风险和优先级 |
| S4_SOLUTION_DESIGN | 按建立任务清单 → 汇总每周负荷 → 检查连续与通勤 → 比较团队分布 → 识别高风险 → 生成排班/减负建议设计首选方案和受限备选方案。 | 方案、责任人、完成标准 |
| S5_HUMAN_CONFIRMATION | 由业务负责人复核输入事实、关键假设和最终成果适用范围。 | 确认记录、未决项和升级项 |
| S6_FINAL_DELIVERY | 生成完整交付成果，执行结构、证据、安全、品牌和独立安装检查。 | 最终成果、范围限制和复盘指标 |

## 6. 核心成果

- `工作负荷表`
- `热区`
- `调整方案`

## 7. 差异化与排重

- 与现有产品：课时统计只算课时；薪酬计算算工资；本产品审查教学与非教学综合负荷。
- 排重检查：部分重叠；共享课表与课时，但输出负荷风险和工作设计建议。
- 独立理由：输入任务标准工时即可独立审计。

## 8. 安全与人工门禁

- 复核角色：业务负责人
- 复核范围：输入事实、关键假设和最终成果适用范围
- 不调用外部收费API。
- 不自动修改外部系统、执行退款、审批合同、处分员工或联系外部人员。
- 高风险产品完成状态必须确认人工复核。
